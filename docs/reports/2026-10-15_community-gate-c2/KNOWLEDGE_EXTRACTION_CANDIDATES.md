## 候选 1：API 模式不能静默回退到本地成功

- 场景：同一套 UI 同时支持静态演示和真实账户。
- 候选原则：运行模式必须在启动时显式选择；真实 API 失败应显示错误，不能切换为可写 `localStorage` 并向用户展示成功。
- 证据：浏览器阻断 `/api/community/*` 后内容卡为 0，显示服务端不可用；自动化断言通过。
- 可复用范围：内容社区、工作台、AI 应用和电商演示。

## 候选 2：本地状态迁移必须降级可信结论

- 场景：将浏览器演示数据迁移到真实账户。
- 候选原则：可迁移用户意图和自有草稿，但客户端的 verified/approved/published 不得提升为服务端可信状态；应先预览、再确认，并保留原副本。
- 证据：Chrome 实测本地 published 草稿回读为 draft，verified 注释回读为 pending，本地 key 仍存在。
- 可复用范围：离线应用、Demo 转正式账户、匿名转注册用户。

## 候选 3：状态机、版本快照和审计事件应同事务提交

- 场景：创作者投稿被多人更新和审核。
- 候选原则：当前态、不可变版本和审计事件必须在同一事务内写入；乐观锁失败返回冲突，不得静默覆盖。
- 证据：故意制造重复事件主键触发回滚后，当前态仍为 version 1，版本和事件数量没有部分增长；PostgreSQL 并发更新只有一个成功。
- 可复用范围：审核流、订单状态、内容发布和配置变更。

## 候选 4：持久化 E2E 断言不能假设环境为空

- 场景：真实测试工作区会保留历史发布内容。
- 候选原则：验收应验证版本化基线和业务不变量，而不是断言总记录数等于初始种子数；测试数据应有命名空间和可识别 provenance。
- 证据：首次 HTTP 验收因历史发布内容使总数超过 10 而误报；改为校验 10 条 `demo_seed` 后重跑通过。
- 可复用范围：staging、共享测试库、增量迁移和回归测试。

## 候选 5：破坏性数据库 fixture 必须有环境硬门禁

- 场景：集成 fixture 使用 `TRUNCATE ... CASCADE`。
- 候选原则：仅凭数据库 URL 环境变量不足以防误连；fixture 应同时校验独立数据库名、测试项目标识和显式 destructive-test opt-in，并优先创建临时 Docker project/volume。
- 证据：本轮发生误指向开发数据库并触发恢复；最终集成组改在 `haha-c2-pgtest` 独立 volume 中执行并清理。
- 可复用范围：所有会 truncate、drop、重建 schema 的集成测试。

## 候选 6：UI 选项必须有端到端契约证据

- 场景：搜索页展示最新、热门、核验等级排序。
- 候选原则：UI 控件存在不等于功能存在；适配器必须传参，API 必须校验，服务端必须执行，并有负向契约测试。
- 证据：扫描发现 sort 未传递；修复后测试验证合法排序与非法值 422。
- 可复用范围：筛选、分页、导出、排序和权限开关。

## 候选 7：生产构建和会临时移动路由的静态构建必须串行

- 场景：Next.js 同仓库同时输出 BFF 生产站和纯静态 Demo。
- 候选原则：若静态脚本会临时移动动态 API 路由，两种构建禁止并行，否则会产生非确定性假失败或错误产物。
- 证据：本轮串行执行 `npm run build` 与 `npm run build:demo` 均通过。
- 可复用范围：多目标前端构建和 CI matrix 设计。

## 候选 8：浏览器 E2E 应等待业务完成条件而不是页面静态文案

- 场景：服务端渲染外壳先出现，客户端再请求 API 并提交内容卡片。
- 候选原则：导航完成和静态标题出现不等于数据加载完成；应轮询可观测业务条件（如内容卡数量和可信标识），设置明确超时并保留失败指标。
- 证据：全新 CI 数据库首次 bootstrap 返回 200 后，旧脚本立即读取到 0 张卡；改为等待 API 内容进入 DOM 后，同一冷启动环境通过。
- 可复用范围：React hydration、异步数据页、流式渲染和冷启动验收。

## 候选 9：客户端分页必须在共享契约层执行边界归一化

- 场景：搜索 UI 请求 60 条，FastAPI 明确限制最多 50 条。
- 候选原则：页面使用共享常量，API 适配器再次归一化；服务端仍保留独立校验，防止其他客户端越界。
- 证据：真实浏览器先得到 422；修复后契约测试覆盖 60→50、0→1 和小数截断，浏览器搜索通过且失败 HTTP 为 0。
- 可复用范围：分页、批量导出、上传大小和其他跨端数值边界。
