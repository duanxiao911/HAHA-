# Gate C1 用户中心收口｜知识提取候选

本文件仅是复核队列，不自动写入全局知识树。

## 候选 1：首次建号必须使用数据库原子幂等写

- 类别：数据完整性/并发
- 证据：真实 Chrome 同时请求 user-center 与 workbench 时复现 `users_pkey` 冲突；原子 insert-ignore 后独立 PostgreSQL 四线程测试通过。
- 原则：select-then-insert 不能承担并发幂等保证；唯一约束与冲突处理必须在同一数据库操作中完成。
- 边界：适用于可安全复用既有行的 bootstrap；需要返回冲突差异时不能静默忽略。
- 置信度：高；已脱敏。
- 下一步：在更多首次创建路径复查同类模式。

## 候选 2：React effect 不应依赖会被自身操作替换的聚合对象

- 类别：前端状态/可靠性
- 证据：记录历史会更新本地 snapshot，`content` 对象引用变化触发 cleanup，导致 `busyAction` 永不释放；改用稳定字段依赖后真实 E2E 通过。
- 原则：异步 effect 的取消生命周期应由稳定业务键控制，不能由自身会修改的派生对象控制。
- 边界：对象确实代表不同任务时仍应取消旧操作。
- 置信度：高；已脱敏。
- 下一步：扫描其他带本地写入的异步 effect。

## 候选 3：真实浏览器验收必须等待可观察的 hydration 就绪信号

- 类别：E2E 测试
- 证据：仅等待 SSR 选择器会点击尚未挂载处理器的静态按钮；改为等待历史同步反馈后，交互断言稳定。
- 原则：SSR 页面“元素存在”不等于客户端交互可用，应等待真实业务就绪信号。
- 边界：纯服务端链接无需 hydration 等待。
- 置信度：高；已脱敏。
- 下一步：抽取统一的 `wait_for_interactive` 测试助手。

## 候选 4：Gate 边界应体现在信息架构而非仅写在报告里

- 类别：产品架构/UI
- 证据：身份切换移至账户菜单，学习者与买家只展示已实现能力和阻断原因；专业身份才显示工作台。
- 原则：未实现域不应通过空工作台或虚假数据营造完成感。
- 边界：有真实最小闭环的模块可以先提供受限工作台。
- 置信度：中高；已脱敏。
- 下一步：以同样方式审计 C2/C3/D/E 的入口和空状态。

下一迭代建议：优先 Gate C2 的真实内容账户迁移，再进入 Gate C3 学习成长；不要把 C1 真实聚合误写成完整学习成就系统。
