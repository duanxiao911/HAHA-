# Gate F 综合升级计划

## 目标

把已完成的 A–E 内部闭环接入可重复、可失败、可审计的生产工程门禁，同时保持
“不是 Production Candidate / Production Ready”的诚实状态，直到外部环境门禁真正通过。

当前状态（2026-10-19）：F1–F4 的仓库实现与隔离准发布演练通过；F5 当前提交远端 CI 为
`UNKNOWN`；F6 因缺少获批外部环境与负责人签署为 `BLOCKED`。

## 工作流

| 阶段 | 输出 | 通过条件 |
|---|---|---|
| F1 扫描 | 真实资产和缺口清单 | 不依赖旧报告推断实现 |
| F2 安全 | 指标认证、发布预检、烟测 | 无凭据 401、错配配置拒绝启动 |
| F3 恢复 | 当前 schema 备份/隔离恢复 | revision 与跨模块表计数一致 |
| F4 容量 | 并发只读烟测 | 错误率、P95、P99 全部低于阈值 |
| F5 CI | 平台契约、浏览器、恢复与容量门禁 | GitHub CI 真实通过 |
| F6 外部门禁 | TLS、告警、异地备份、staging 回滚 | 真实环境证据齐全 |

## 依赖顺序

安全配置契约 → 单元/静态检查 → Compose 实栈 → 当前数据恢复 → 容量烟测 → 浏览器回归
→ 外部 staging → 生产候选决策。

## 风险控制

- 恢复脚本仅接受自动生成的 `haha_restore_*` 数据库名。
- 默认在验证后删除隔离数据库；源数据库不执行 drop、truncate 或 restore。
- 负载默认命中 `/ready`，写端点不得在未提供专用测试数据与幂等策略时压测。
- 真实凭据只通过环境变量；输出不得包含令牌。
- 外部服务不可用时标记 `BLOCKED` 或 `UNKNOWN`，不降级为 Mock 通过。

## 结束标准

本地 Gate F 可在全部自动化门禁通过后标记为阶段 PASS；完整平台只有在外部 staging
和既有业务阻断全部完成后，才可进入 Production Candidate 评审。
