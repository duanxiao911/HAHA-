# 架构决策矩阵

| 方案 | 优点 | 代价/风险 | 决策 |
|---|---|---|---|
| 保留模块化单体并扩展 commerce bounded context | 复用账户、权限、事务、迁移、CI；最小风险 | 需要拆分现有大页面和 main.py API 区段 | **选择** |
| 在现有系统旁新建独立商城服务 | 隔离明显 | 第二套身份/数据/部署，分布式事务和运维成本不成立 | 拒绝 |
| 直接嵌入通用聊天机器人 | 开发快 | 无实时商品约束、不可审计、容易幻觉和越权 | 拒绝 |

## ADR-COMMERCE-002

采用“确定性交易内核 + 工具约束型导购工作流”：

1. PostgreSQL 商品、SKU、价格和库存是唯一事实源。
2. 服务端 Search/Catalog Service 完成过滤、排序和候选召回。
3. DeepSeek 只负责意图提取、追问、候选解释和组合建议。
4. 推荐结果必须携带真实 product/SKU ID、价格库存版本与理由。
5. 加购、结算、支付、售后永远重新经过 CommerceService 权限和状态校验。
6. V1 使用确定性工作流，不引入 Multi-Agent、向量数据库或新微服务。
