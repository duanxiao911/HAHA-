# 商城与 AI 导购信息架构预览

状态：`AWAITING_USER_CONFIRMATION`。确认前不实施重大前端结构变化。

## 页面分工

1. `/commerce`：买家商城首页，只负责发现、搜索、策展和进入导购。
2. `/commerce/products/[id]`：商品详情、媒体、SKU、来源层级、文化关联与加购。
3. `/commerce/cart`：购物车与结算确认。
4. `/commerce/orders`：订单、履约和售后。
5. `/commerce/advisor`：完整导购会话；桌面端也可从商城右侧面板进入。
6. `/commerce/manage`：卖家经营工作台，从“专业工作台”进入，不混在买家商城标签中。
7. `/review/commerce`：内部商品审核，从内部审核工作台进入，不对公众展示入口。

## 桌面首页

```text
┌ 顶部平台导航 ───────────── 搜索商品/文化主题 ─── 购物车 ─ 头像 ┐
├──────────────────────────────────────────────────────────────┤
│ 当季策展：一张主视觉 + 主题说明 +「逛本季新品」               │
│                                              ┌ AI 导购 ────┐ │
│ 快捷任务：送礼 / 居家 / 入门收藏 / 按预算找   │ 你好，需要… │ │
│                                              │ [描述需求]   │ │
│ 分类：织绣  陶瓷  木作  金工  文创礼赠        │ 推荐任务 chips│ │
│                                              └─────────────┘ │
│ 精选商品网格：真实图片、名称、价格、来源状态、创作者/店铺      │
│ 内容导购：相关短视频/工艺故事（明确内容与商品关系）            │
└──────────────────────────────────────────────────────────────┘
```

原则：AI 面板默认安静停靠，不自动弹窗遮挡；首次进入只出现一句欢迎和 3—4 个高频任务。用户开始对话后进入可恢复会话。

## AI 导购会话

```text
┌ 返回商城   专业导购                                  新对话 ┐
│ AI：先问一个最有信息量的问题（预算/对象/用途三选一）           │
│ 用户：送老师，500 元以内，希望有文化故事                       │
│ AI：给 3 个真实商品卡 + 匹配理由 + 差异比较                    │
│ [商品图] [价格] [库存状态] [来源层级] [详情] [加入备选]         │
│ 已选 2 件：比较 / 加入购物车草案                               │
│ ─────────────────────────────────────────────────────────── │
│ 输入需求…                               [发送]                │
└──────────────────────────────────────────────────────────────┘
```

购买路径：`推荐 → 查看依据/详情 → 用户选择 SKU → 加入购物车 → 确定性结算确认`。AI 不直接支付。

## 移动端

- 商城首页顶部保留搜索；导购作为搜索下方醒目但不遮挡的入口。
- 完整对话使用独立页面，不用覆盖全屏的悬浮气泡。
- 底部平台导航保持“首页/社区/学习/电商/我的”；购物车在电商页顶部。
- 商品卡至少单列，关键信息不靠 hover；底部固定输入框避开系统安全区。

## 状态

- Loading：商品骨架与导购初始化分别显示，互不阻塞。
- Empty：说明无匹配并提供放宽条件，不伪造推荐。
- Error：保留用户输入和当前购物车，可重试或回普通搜索。
- Permission：买家能力自动开通；商家管理明确引导申请，不出现内部角色入口。
- Success：加购后显示购物车数量与“继续逛/去结算”。
- AI Blocked：模型不可用时明确切换到普通搜索与人工策展，不用模板回答冒充 AI。
